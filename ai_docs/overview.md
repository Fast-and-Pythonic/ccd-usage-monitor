# Overview

## Stack
- Rust 1.97, edition 2024 (as generated by `cargo init`)
- `slint` + `slint-interpreter` + `slint-build` 1.17.1, pinned exactly, with
   the winit backend and the femtovg renderer named rather than left to
   `default` — G05 was a renderer changing underneath and taking transparency
   with it (wanted, not required: A20), and every figure in these docs was
   measured on femtovg
- `ureq` 3 (rustls) for the one HTTP call, `serde`/`serde_json`, `toml` and
   `toml_edit` (the config is edited in place, not rewritten — A22),
   `chrono`, `dirs`, `tray-icon` 0.24, `windows-sys` and `raw-window-handle`
   for the window itself (A10, A24)
- Release profile is LTO + strip; the result is a single `.exe` with no runtime
   dependencies beyond the OS.
- Three build profiles, measured on the development machine (a 2014 laptop,
   two cores, four threads), time to rebuild after touching one file:
   `release` 8–10 min; `dev` 32 s for a `.rs` file, 21 s for `.slint`; `quick`
   (release without LTO, sixteen codegen units, incremental — `Cargo.toml`)
   10 s and 12 s, after a first build from scratch of 21 min. `quick` is for
   running the widget while working on it, `release` for installing; the
   commands are in README

## Source layout
The file layout follows the three layers of A19: what the widget knows
(`runtime.rs`), what it says (`view.rs`), and how it draws (`slint_ui.rs` plus
the theme it reads).

| File | Responsibility |
|---|---|
| `main.rs` | mode dispatch: widget, `--demo`, `--bridge`, `--print`, `--probe-api`, `--sources`, `--sessions`, `--serve` |
| `model.rs` | `Snapshot`, `Window`, `ContextInfo`, `Source`; merge rules between sources |
| `state.rs` | the shared state file — schema, locking, atomic write, pruning; parsing of the status-line payload |
| `api.rs` | token reading, the usage-endpoint request, response parsing, poller thread with its wake channel |
| `desktop.rs` | the Claude desktop app's own usage history (A08) |
| `session.rs` | the conversation transcripts: which session, and how full its context window is (A18) |
| `history.rs` | the widget's own log of past readings, and the rate read out of it (A17) |
| `pace.rs` | countdowns, reset labels, days until reset, daily allowance, pace verdict |
| `bridge.rs` | `--bridge`: stdin payload → state file → ANSI line for the terminal |
| `runtime.rs` | the four sources pumped and merged, the poller's channel, age filtering, the history log. No drawing (A19) |
| `view.rs` | snapshot and runtime state → the words, figures and verdicts a person reads, and the composition of the pill itself (`cells`, `bars`); colour as meaning, not as RGB. No drawing (A19) |
| `tray.rs` | the tray icon and its menu, as a source of commands rather than a handler |
| `serve.rs` | `--serve`: the snapshot as JSON on loopback, for a widget in somebody else's panel (A21). No drawing |
| `config.rs` | `config.toml` in the data folder beside the executable (A36) — sectioned, edited in place so comments survive (A22) |
| `schema.rs` | every setting described once: its kind, its bounds, its section, its words, its card in the settings window and what it depends on (A22, A33) |
| `geometry.rs` | `window.json` — where the windows were left; the widget's own memory, not a setting (A22) |
| `slint_ui.rs` | the front end: the pill and panel windows, the theme contract, the window policy over the HWND, the tray (A20, A24, A25) |
| `settings_ui.rs` | the settings window, walked out of `schema.rs` — pages of cards in, values back out, rows rewritten in place (A22, A33) |
| `themes/pill.slint` | the default appearance, compiled in; written to the data folder on first run so it can be edited (A24) |
| `settings/` | the data folder of any build inside this repository (A36). Machine state, ignored by git — except `theme.slint`, the live, hand-tuned theme the widget loads here |
| `ui/settings.slint` | the form, compiled in through `build.rs`; a side list of pages, cards of rows drawn by the control each asks for, and no knowledge of any setting (A33) |
| `win.rs` | Win32 frame surgery: no DWM shadow and no non-client frame (A10) |

## Data flow
```
Claude Code ──stdin JSON──> ccd-usage-monitor --bridge ──> <data folder>\state.json
                                                          │ mtime poll, 250 ms
desktop app ──every ~15 min──> plan-usage-history.json ────┤
                                                          │
usage endpoint ──poller, 180 s + wake-ups──────────────────┤
                                                          │
transcripts ──~/.claude/projects/**/<uuid>.jsonl───────────┤
              (tree rescanned every 30 s; one mtime        │
               stat of the chosen file between scans)      ▼
                                          merge field by field (A03) ──> pill
```

The first three carry the quota windows; the fourth carries the context figure
(A18), and the bridge carries both. `ccd-usage-monitor --sources` prints what
each of the four says right now, side by side; it is the first thing to run when
a figure looks wrong. `--sessions` does the same for the transcripts.

## Cost at rest
Idle, with the pill visible: 51 MB working set of which 21 MB is private, and
0.109 s of CPU over 70 seconds — about a sixth of a percent of one core. The
memory is dominated by the GPU stack, not by the app. The binary is 17.9 MB.

The comparison with the egui front end this replaced — and the method behind
all of these numbers — is in A20, which is the decision they were taken for.
They are not repeated here: the same figure in two files disagrees with itself
within a month.

The CPU figure is a `TotalProcessorTime` delta over a long window on purpose. A
sample of a second or two rounds it to "0.0 %", which reads as a measurement and
is not one.

The transcript source adds a tree walk on its own clock, not on the 250 ms tick:
enumerating 86 files across 16 directories measured ~98 ms, and tail-reading all
of them ~236 ms, against a default `session_scan_secs` of 30. Between scans the
cost is one `stat` of the single chosen file, which is why the scan interval can
be raised without the figure going stale.
